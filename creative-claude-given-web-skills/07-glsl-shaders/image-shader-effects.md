# SKILL: image-shader-effects

**Layer:** 07 — GLSL & Shader Programming

**Goal:** Build performant, reusable image effects in GLSL by transforming texture coordinates, sampling and compositing images, and controlling effects with uniforms.

## Why This Matters (Senior Perspective)

Image shaders are one of the highest-leverage tools in creative web development. A small fragment shader can create hover distortion, duotone treatments, chromatic aberration, grain, blur-like effects, reveal transitions, and interactive image surfaces without layering many DOM elements or running a chain of CPU-side image operations. The GPU evaluates the shader for every fragment in parallel, which makes it well suited to effects that vary smoothly across an image.

The main challenge is not writing a clever equation; it is understanding the rendering pipeline and the constraints around it. Texture coordinates may not match the displayed image's aspect ratio, color values may be in different color spaces, and a shader can sample outside the texture bounds. A visually convincing effect can still be fragile if it breaks on portrait images, produces edge streaks, ignores device pixel ratio, or does unnecessary work on every frame.

Senior-level implementation starts with a simple baseline, exposes only meaningful controls as uniforms, and adds complexity deliberately. Keep image loading, layout, and accessibility in the DOM; use the shader for the visual treatment. Provide a normal image fallback, respect reduced-motion preferences, and profile the effect on mobile GPUs. This separation makes the effect easier to maintain, reuse across projects, and present as a polished portfolio interaction.

## Core Concepts

### 1. The fragment shader is a per-pixel image processor

A fragment shader runs for each fragment generated by the geometry. For a flat plane, the fragment's interpolated UV coordinate identifies a location in the texture. The shader samples the image at that coordinate, modifies the returned color, and writes the result.

The mental model is: **UV in → texture sample → color transformation → output**. Start with the unmodified sample so you can confirm the texture, UVs, and color pipeline before introducing effects.

```glsl
uniform sampler2D uImage;
varying vec2 vUv;

void main() {
  vec4 imageColor = texture2D(uImage, vUv);
  gl_FragColor = imageColor;
}
```

- `uImage` is the texture supplied by the host application.
- `vUv` is the interpolated texture coordinate, typically in the range 0–1.
- `texture2D` samples a texture in GLSL ES 1.00 / WebGL 1 style shaders.
- `gl_FragColor` is the output color in that same shader version.

**Gotcha:** Three.js shader syntax depends on the renderer and shader version. The examples in this skill use GLSL ES 1.00 conventions because they are widely recognizable in custom Three.js shader materials. For GLSL 3 / WebGL 2, use the corresponding `in`, `out`, and `texture()` conventions.

### 2. UV coordinates are the effect's coordinate system

UVs describe the position within a texture, not the position in CSS pixels. `(0.0, 0.0)` is one corner and `(1.0, 1.0)` is the opposite corner, with the exact visual orientation depending on the geometry and texture setup. UV-space math makes an effect resolution-independent: the same equation can work on a small thumbnail and a large hero image.

```glsl
vec2 centeredUv = vUv - 0.5;
float distanceFromCenter = length(centeredUv);
```

Subtracting `0.5` moves the origin to the center. This is useful for radial distortion, vignette, lens effects, and center-based reveals.

**Gotcha:** A circular effect in UV space may look elliptical when the image is not square. Correct distance calculations by accounting for the image aspect ratio when the effect should be circular in display space.

### 3. Texture sampling is not free

Each `texture2D` call asks the GPU to sample texture data. A single sample is generally inexpensive, but blur kernels, multi-channel offsets, and layered compositing can multiply the cost. Sample only what the effect needs, and avoid loops with large or data-dependent bounds in a real-time fragment shader.

```glsl
vec4 baseColor = texture2D(uImage, vUv);
vec4 redSample = texture2D(uImage, vUv + vec2(uChromaticOffset, 0.0));
```

A chromatic aberration effect may use three samples to separate channels. A blur effect may need many more. Treat sample count as a budget, particularly for full-screen effects and mobile devices.

### 4. Uniforms are the public controls of the effect

Uniforms let JavaScript change effect parameters without rebuilding the shader program. Use them for pointer position, progress, intensity, time, image aspect ratio, and color controls. Keep the shader responsible for the per-pixel math and the application responsible for interaction state.

```glsl
uniform float uIntensity;
uniform float uProgress;
uniform vec2 uPointer;
```

Use descriptive names and define a clear range for each control. For example, `uProgress` can be constrained to `0.0–1.0`; `uIntensity` can be a small normalized value instead of an arbitrary number that causes extreme distortion.

### 5. Color operations need deliberate ordering

Image treatments often combine sampling, luminance, contrast, saturation, tinting, and opacity. The order changes the result. A useful baseline is to compute luminance from the sampled RGB values, mix toward grayscale for saturation, then apply contrast or tint. Use clamping where the operation can produce values outside the display range.

```glsl
float luminance(vec3 color) {
  return dot(color, vec3(0.2126, 0.7152, 0.0722));
}

vec3 grayscale = vec3(luminance(imageColor.rgb));
vec3 adjusted = mix(grayscale, imageColor.rgb, uSaturation);
```

The weights approximate perceptual luminance. Color management still matters: the shader's values and the renderer's output pipeline must agree about color space. Avoid assuming that arbitrary RGB values are automatically linear or sRGB in every renderer configuration.

### 6. Texture edges need a policy

UV distortion can push samples beyond the original image. Depending on texture wrapping, those samples may repeat, mirror, clamp, or produce unexpected edge behavior. For editorial image effects, clamping plus a fade often looks more intentional than repeating the image.

```glsl
vec2 safeUv = clamp(distortedUv, vec2(0.001), vec2(0.999));
vec4 color = texture2D(uImage, safeUv);
```

The inset avoids sampling exactly at the boundary on some texture configurations. It is not a universal fix: the host texture's wrap mode and padding strategy should be chosen intentionally.

### 7. Aspect ratio is part of the visual design

A shader should know whether it is operating in UV space, plane-local space, or screen space. If a radial effect should be round on screen, scale one axis using the displayed image aspect ratio. If the image uses `cover`, the host may crop the texture before the shader sees it; if it uses `contain`, empty regions may need to be handled separately.

```glsl
uniform float uAspect;

vec2 aspectCorrect(vec2 uv) {
  vec2 p = uv - 0.5;
  p.x *= uAspect;
  return p;
}
```

Be consistent about whether `uAspect` means width divided by height or the inverse. Document the convention in both JavaScript and GLSL.

### 8. Alpha is data, not decoration

If a texture has transparency, preserve its alpha unless the effect intentionally changes it. For compositing, ensure the material's transparency settings and the shader's output agree. If you create a mask, decide whether it controls alpha, RGB, or both.

```glsl
vec4 color = texture2D(uImage, vUv);
float mask = smoothstep(0.25, 0.75, color.r);
gl_FragColor = vec4(color.rgb, color.a * mask);
```

**Gotcha:** A shader writing alpha below 1 does not by itself guarantee the expected visual result. The material and render pipeline must enable the appropriate transparency and blending behavior.

## Integration Patterns

### Pattern 1: A minimal image-shader material

**Use when:** You need a known-good starting point for any custom image effect.

The plane's UVs are passed from the vertex shader to the fragment shader. The material has one image uniform and renders the sampled image unchanged. Keep this baseline handy; when an effect fails, temporarily return to this shader to isolate whether the problem is texture loading, geometry UVs, or effect math.

```js
import * as THREE from 'three';

const vertexShader = `
  varying vec2 vUv;

  void main() {
    vUv = uv;
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
  }
`;

const fragmentShader = `
  uniform sampler2D uImage;
  varying vec2 vUv;

  void main() {
    gl_FragColor = texture2D(uImage, vUv);
  }
`;

const texture = new THREE.TextureLoader().load('/images/hero.jpg');
texture.colorSpace = THREE.SRGBColorSpace;

const material = new THREE.ShaderMaterial({
  uniforms: {
    uImage: { value: texture }
  },
  vertexShader,
  fragmentShader
});

const geometry = new THREE.PlaneGeometry(2, 1.25);
const mesh = new THREE.Mesh(geometry, material);
scene.add(mesh);
```

For a production page, handle texture loading failures, dispose of the texture and material when the component unmounts, and use a DOM image as the accessible fallback. Set plane dimensions and camera framing deliberately rather than assuming the example geometry will fit every viewport.

### Pattern 2: Grayscale, saturation, and tint

**Use when:** You want a reusable editorial color treatment that can be tuned per image.

The shader computes luminance, blends between grayscale and the original color, then mixes toward a tint. This ordering preserves a predictable base and makes the controls easy to expose in a CMS or design system.

```glsl
uniform sampler2D uImage;
uniform float uSaturation;
uniform vec3 uTint;
uniform float uTintStrength;
varying vec2 vUv;

void main() {
  vec4 sampled = texture2D(uImage, vUv);
  float luminance = dot(sampled.rgb, vec3(0.2126, 0.7152, 0.0722));
  vec3 grayscale = vec3(luminance);
  vec3 saturated = mix(grayscale, sampled.rgb, uSaturation);
  vec3 tinted = mix(saturated, saturated * uTint, uTintStrength);

  gl_FragColor = vec4(tinted, sampled.a);
}
```

Suggested ranges: `uSaturation` from `0.0` (grayscale) to `1.0` (original saturation), and `uTintStrength` from `0.0` to a modest value such as `0.35`. A value above `1.0` is possible but can quickly crush highlights or create clipping.

### Pattern 3: Soft vignette

**Use when:** You want to draw attention toward the center without adding a separate overlay element.

Distance is measured from the center in aspect-corrected UV space. `smoothstep` creates a soft transition rather than a hard circular boundary.

```glsl
uniform sampler2D uImage;
uniform float uVignetteStrength;
uniform float uVignetteStart;
uniform float uVignetteEnd;
uniform float uAspect;
varying vec2 vUv;

void main() {
  vec4 color = texture2D(uImage, vUv);

  vec2 centered = vUv - 0.5;
  centered.x *= uAspect;
  float distanceFromCenter = length(centered);
  float vignette = smoothstep(uVignetteStart, uVignetteEnd, distanceFromCenter);
  float brightness = 1.0 - vignette * uVignetteStrength;

  gl_FragColor = vec4(color.rgb * brightness, color.a);
}
```

Tune the start and end values for the aspect ratio and composition. A strong vignette may look dramatic in a demo but can muddy faces and product photography. Keep the strength subtle by default.

### Pattern 4: Chromatic aberration

**Use when:** You want a lens-like RGB split for hover, transitions, or stylized artwork.

Sample the red and blue channels at slightly different UVs while taking green from the center sample. The offset should be small and typically increase with distance from the center or with interaction progress.

```glsl
uniform sampler2D uImage;
uniform float uOffset;
uniform float uAspect;
varying vec2 vUv;

void main() {
  vec2 centered = vUv - 0.5;
  centered.x *= uAspect;
  float radialStrength = smoothstep(0.05, 0.7, length(centered));
  vec2 offset = normalize(centered + vec2(0.0001)) * uOffset * radialStrength;
  offset.x /= uAspect;

  vec4 centerSample = texture2D(uImage, vUv);
  float red = texture2D(uImage, vUv + offset).r;
  float blue = texture2D(uImage, vUv - offset).b;

  gl_FragColor = vec4(red, centerSample.g, blue, centerSample.a);
}
```

This version uses three texture samples. Clamp the offset and test on high-contrast edges, where the split is most visible. Avoid large offsets unless the effect is intentionally glitchy.

### Pattern 5: Pointer-driven magnification

**Use when:** A portfolio image should respond to pointer position like a lens or inspection window.

Map the pointer to UV coordinates, measure distance from it, and remap UVs inside a radius. The example gently magnifies the area around the pointer; the host must update `uPointer` in the same UV coordinate system used by the shader.

```glsl
uniform sampler2D uImage;
uniform vec2 uPointer;
uniform float uRadius;
uniform float uStrength;
varying vec2 vUv;

void main() {
  vec2 delta = vUv - uPointer;
  float distanceToPointer = length(delta);
  float influence = 1.0 - smoothstep(0.0, uRadius, distanceToPointer);

  vec2 sampleUv = vUv - delta * influence * uStrength;
  sampleUv = clamp(sampleUv, vec2(0.001), vec2(0.999));

  gl_FragColor = texture2D(uImage, sampleUv);
}
```

The sign and strength determine whether the region appears magnified or displaced; test with a grid texture before tuning it on a photograph. Convert pointer coordinates carefully: DOM coordinates are usually top-left-origin pixels, while UVs are normalized and may have an inverted Y axis.

### Pattern 6: Progress-based image reveal

**Use when:** You need a shader-controlled transition between hidden and visible image states.

The shader creates a soft horizontal reveal driven by a `0.0–1.0` progress value. It preserves the sampled RGB and uses a mask for alpha. If the effect is used on an opaque background, an RGB mask may be more appropriate than transparency.

```glsl
uniform sampler2D uImage;
uniform float uProgress;
uniform float uFeather;
varying vec2 vUv;

void main() {
  vec4 imageColor = texture2D(uImage, vUv);
  float edge = uProgress * (1.0 + uFeather) - uFeather * 0.5;
  float mask = smoothstep(edge - uFeather, edge + uFeather, vUv.x);

  gl_FragColor = vec4(imageColor.rgb, imageColor.a * mask);
}
```

Animate `uProgress` with GSAP or your application's animation system. Keep the shader stateless: the current progress value should fully describe the reveal, so it can be reversed or scrubbed without special cleanup.

### Pattern 7: Subtle animated grain

**Use when:** You want a filmic surface texture that adds life to a static image.

Noise should be subtle and should not require a costly random-number operation for every effect stage. This hash-based example is compact but can show visible patterns; for high-end work, consider a small tiled noise texture or blue-noise texture instead.

```glsl
uniform sampler2D uImage;
uniform float uTime;
uniform float uGrainAmount;
varying vec2 vUv;

float hash(vec2 p) {
  return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453);
}

void main() {
  vec4 color = texture2D(uImage, vUv);
  float grain = hash(floor(vUv * vec2(900.0, 600.0) + uTime * 30.0)) - 0.5;
  vec3 grainColor = color.rgb + grain * uGrainAmount;

  gl_FragColor = vec4(clamp(grainColor, 0.0, 1.0), color.a);
}
```

Use a very small `uGrainAmount` and avoid updating time when the image is not visible. The fixed resolution in this example is illustrative; a production version should base grain scale on the intended visual resolution or use a texture-based noise source.

## Advanced Patterns

### 1. Aspect-correct radial distortion

**Use when:** A lens, ripple, or radial displacement must look consistent across landscape and portrait images.

The key is to measure distance in display-like coordinates and convert the displacement back into UV space. The shader below adds a sinusoidal ripple whose strength fades with distance. It is a visual starting point, not a physically accurate lens model.

```glsl
uniform sampler2D uImage;
uniform float uTime;
uniform float uStrength;
uniform float uAspect;
varying vec2 vUv;

void main() {
  vec2 centered = vUv - 0.5;
  vec2 displaySpace = vec2(centered.x * uAspect, centered.y);
  float radius = length(displaySpace);
  float wave = sin(radius * 32.0 - uTime * 2.0);
  float falloff = 1.0 - smoothstep(0.0, 0.75, radius);

  vec2 direction = normalize(displaySpace + vec2(0.0001));
  vec2 displacementDisplay = direction * wave * uStrength * falloff;
  vec2 displacementUv = vec2(displacementDisplay.x / uAspect, displacementDisplay.y);
  vec2 sampleUv = clamp(vUv + displacementUv, vec2(0.001), vec2(0.999));

  gl_FragColor = texture2D(uImage, sampleUv);
}
```

Keep `uStrength` small; UV displacement is normalized, so even a small numeric value can shift the image noticeably. If the effect animates continuously, pause or reduce updates when the canvas is off-screen.

### 2. Two-texture blend with a soft mask

**Use when:** You need a crossfade, wipe, or image-to-image transition inside one shader.

Both textures should have compatible UV framing. If their aspect ratios differ, prepare matching crops or pass separate UV transforms; otherwise the transition can feel like the image itself is stretching.

```glsl
uniform sampler2D uImageA;
uniform sampler2D uImageB;
uniform float uProgress;
uniform float uSoftness;
varying vec2 vUv;

void main() {
  vec4 a = texture2D(uImageA, vUv);
  vec4 b = texture2D(uImageB, vUv);

  float threshold = vUv.x - uProgress;
  float mask = smoothstep(-uSoftness, uSoftness, threshold);
  vec4 blended = mix(b, a, mask);

  gl_FragColor = blended;
}
```

For a plain crossfade, use `mix(a, b, uProgress)`. For a directional wipe, use a threshold derived from UVs. The example's direction and starting image are easy to reverse; name the variables according to the intended transition direction in the production version.

### 3. Luminance-driven duotone

**Use when:** You want a branded, art-directed color grade rather than a simple tint.

Map darker pixels toward one color and brighter pixels toward another. A contrast parameter controls how sharply luminance maps across the gradient.

```glsl
uniform sampler2D uImage;
uniform vec3 uShadowColor;
uniform vec3 uHighlightColor;
uniform float uContrast;
varying vec2 vUv;

void main() {
  vec4 color = texture2D(uImage, vUv);
  float luminance = dot(color.rgb, vec3(0.2126, 0.7152, 0.0722));
  float shapedLuminance = clamp((luminance - 0.5) * uContrast + 0.5, 0.0, 1.0);
  vec3 duotone = mix(uShadowColor, uHighlightColor, shapedLuminance);

  gl_FragColor = vec4(duotone, color.a);
}
```

This works well for a consistent project palette. Keep the shadow and highlight colors accessible against surrounding UI, and make sure important content remains recognizable after grading.

### 4. Edge-aware displacement with a mask

**Use when:** You want to distort selected regions while keeping the image boundaries stable.

A mask can be a second texture, a procedural field, or a value computed from UVs. The following procedural mask keeps the strongest displacement near the center and fades it near the edges.

```glsl
uniform sampler2D uImage;
uniform float uStrength;
uniform float uTime;
varying vec2 vUv;

void main() {
  float edgeDistance = min(min(vUv.x, 1.0 - vUv.x), min(vUv.y, 1.0 - vUv.y));
  float edgeMask = smoothstep(0.0, 0.12, edgeDistance);
  float waveX = sin(vUv.y * 18.0 + uTime) * uStrength;
  float waveY = cos(vUv.x * 14.0 - uTime * 0.8) * uStrength;

  vec2 displacedUv = vUv + vec2(waveX, waveY) * edgeMask;
  displacedUv = clamp(displacedUv, vec2(0.001), vec2(0.999));

  gl_FragColor = texture2D(uImage, displacedUv);
}
```

Masking the displacement is usually better than trying to repair broken edges after sampling. If you need a perfectly clean border, use a padded texture or fade the effect to the original sample near the boundary.

### 5. Responsive uniform updates in Three.js

**Use when:** You need to connect the shader to viewport dimensions, pointer position, or a timeline without recompiling the material.

Uniform objects are mutable. Update their `.value` properties rather than creating a new material on every pointer event. Rebuilding materials can cause unnecessary allocations and shader compilation stalls.

```js
const uniforms = {
  uImage: { value: texture },
  uPointer: { value: new THREE.Vector2(0.5, 0.5) },
  uAspect: { value: 1 },
  uProgress: { value: 0 }
};

const material = new THREE.ShaderMaterial({
  uniforms,
  vertexShader,
  fragmentShader
});

function updateImageAspect(width, height) {
  uniforms.uAspect.value = width / Math.max(height, 1);
}

function updatePointer(normalizedX, normalizedY) {
  uniforms.uPointer.value.set(normalizedX, normalizedY);
}

function updateProgress(progress) {
  uniforms.uProgress.value = THREE.MathUtils.clamp(progress, 0, 1);
}
```

Throttle pointer updates only if profiling shows a problem; in many cases, updating one vector uniform is inexpensive. Always ensure normalized pointer coordinates refer to the canvas or image element that actually owns the shader.

## Common Mistakes

| Mistake | Why it fails | Better approach |
|---|---|---|
| Using UVs as if they were CSS pixels | Effect size changes with aspect ratio and framing | Work in normalized UVs and pass aspect ratio when needed |
| Applying large UV offsets | Samples leave the image and create streaks or repeated edges | Clamp coordinates, fade displacement near edges, or pad the texture |
| Recreating the material for every interaction | Causes allocations and may trigger shader compilation | Update existing uniform values |
| Adding many blur samples without profiling | Texture reads can dominate fragment cost | Start with fewer taps, lower resolution, or a pre-blurred texture |
| Ignoring color space | Saturation and brightness can look unexpectedly wrong | Configure texture and renderer color management consistently |
| Forgetting alpha behavior | Masks may render opaque or blend incorrectly | Configure material transparency and output alpha deliberately |
| Hard-coding a portrait or landscape assumption | Radial effects become elliptical or crops feel wrong | Pass dimensions and define an explicit crop/cover policy |
| Animating every frame when hidden | Wastes battery and GPU time | Pause when off-screen or when motion is not needed |
| Using shader effects as the only image representation | Content can disappear if WebGL fails and may be inaccessible | Keep meaningful alt text and a DOM fallback |
| Assuming every device supports the same workload | Low-end GPUs may drop frames or overheat | Test mobile, reduce sample count, and provide a reduced-effect mode |

### Wrong vs. right: uniform updates

**Wrong:** Build a new material for each pointer movement.

```js
// Avoid: repeated allocation and potential shader-program churn.
mesh.material = new THREE.ShaderMaterial({
  uniforms: { uPointer: { value: pointerVector } },
  vertexShader,
  fragmentShader
});
```

**Right:** Keep one material and update the uniform.

```js
// Reuse the existing material and its uniform storage.
material.uniforms.uPointer.value.copy(pointerVector);
```

### Wrong vs. right: safe UVs

**Wrong:** Apply arbitrary displacement and assume the texture edge will look good.

```glsl
vec2 sampleUv = vUv + displacement;
gl_FragColor = texture2D(uImage, sampleUv);
```

**Right:** Clamp or fade the effect according to the desired art direction.

```glsl
vec2 sampleUv = clamp(vUv + displacement, vec2(0.001), vec2(0.999));
gl_FragColor = texture2D(uImage, sampleUv);
```

### Wrong vs. right: expensive blur

**Wrong:** Add dozens of texture samples before establishing that blur is needed.

```glsl
// A large sampling kernel can be expensive on a full-screen plane.
```

**Right:** Begin with a small fixed kernel, benchmark it, and consider downsampling or a precomputed blur texture. If you do implement a blur, choose tap count based on measured quality and frame time rather than visual guesswork alone.

## Performance and Production Checklist

1. Start from a one-sample baseline and add one effect at a time.
2. Keep uniforms normalized and document their intended ranges.
3. Minimize texture samples, especially for large canvases.
4. Avoid unnecessary branching and large loops in fragment shaders.
5. Use `clamp`, masks, or padded textures to control edge behavior.
6. Update uniform values rather than replacing materials.
7. Pause time-based effects when they are not visible.
8. Test on at least one mobile device and one high-density display.
9. Provide a static image fallback and meaningful alternative text.
10. Respect `prefers-reduced-motion` for continuous or intense effects.
11. Dispose of textures, materials, and geometries when no longer used.
12. Verify the renderer's color-space and tone-mapping settings before final color tuning.

## Mental Models

1. **UVs are addresses:** They tell the shader where to read the source image.
2. **A fragment shader is a pixel pipeline:** Sample first, transform second, output last.
3. **Uniforms are controls:** JavaScript supplies changing values; GLSL performs per-pixel work.
4. **Every sample has a cost:** Multi-sample effects should earn their performance budget.
5. **Edges reveal mistakes:** Distortion needs a deliberate boundary policy.
6. **Color order matters:** Luminance, saturation, contrast, and tint are not interchangeable steps.
7. **Fallbacks are part of the design:** WebGL effects should enhance content, not make it unavailable.

## Build Challenge

Create a reusable **Shader Image Gallery** for a creative portfolio. It should demonstrate several treatments while remaining responsive and accessible.

### Requirements

1. Build a Three.js scene containing at least three images with distinct aspect ratios.
2. Implement a baseline image shader and expose uniforms for saturation, vignette, distortion strength, and effect progress.
3. Add at least three selectable treatments: duotone, chromatic aberration, and radial distortion.
4. Add a pointer-responsive lens or distortion interaction that returns to a neutral state when the pointer leaves.
5. Add a progress-driven reveal or image transition that can be scrubbed or reversed.
6. Keep texture sampling and animation costs reasonable; document any multi-sample effects.
7. Handle texture loading and failure states, and preserve a normal DOM image with useful alt text as a fallback.
8. Respect reduced-motion preferences by disabling continuous animation or lowering its intensity.
9. Test portrait, square, and landscape assets without unintended stretching or edge artifacts.
10. Include a short README explaining the shader controls, performance trade-offs, and how to add another effect.

### Success criteria

- All images render with correct framing and no unexplained UV flips.
- Uniform changes update the effect without rebuilding the material.
- The controls behave predictably across all image aspect ratios.
- No obvious edge streaking appears during distortion.
- The gallery remains usable on mobile, with a reduced-motion or static mode.
- The result looks art-directed rather than like a collection of unrelated filters.

### Suggested implementation sequence

1. Render one image with the baseline shader.
2. Add and verify color-space configuration.
3. Add one color treatment and tune it on several image types.
4. Add a UV effect with edge protection.
5. Connect pointer and timeline state through uniforms.
6. Test performance and reduce unnecessary samples.
7. Add accessibility, fallback behavior, and cleanup.
8. Package the shader and its uniform defaults as a reusable component.
